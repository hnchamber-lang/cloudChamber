# Chamber Reorganization & Project Builder

[![tests](https://github.com/hnchamber-lang/cloudChamber/actions/workflows/tests.yml/badge.svg)](https://github.com/hnchamber-lang/cloudChamber/actions/workflows/tests.yml)
[![python](https://img.shields.io/badge/python-3.10%20%7C%203.11%20%7C%203.12-blue)](#prerequisites)

Tooling to (1) reorganize `D:\Chamber` into a standardized instrument-serial
based layout (`01_instruments/{MODEL}_SN{serial}/`) and (2) build
per-experiment project folders from a user-authored `namelist.yaml` — via CLI
or a PyQt5 GUI.

## Files in this folder

| File | Purpose |
|---|---|
| `instruments.yaml` | Single source of truth — catalog of all instruments, their serials, legacy paths, file patterns, and date parsers. |
| `serials_to_fill.md` | Checklist of 9 instruments whose serial number is still unknown; update after hardware label inspection. |
| `reorganize.py` | One-time migration: renames / merges legacy folders into `01_instruments/{MODEL}_SN{serial}/`. |
| `build_project.py` | CLI that consumes a namelist and materializes a project folder under `03_projects/{project_name}/`. |
| `chamber_gui.py` | PyQt5 GUI wrapping `build_project.py`; handles namelist authoring + preview + execute. |
| `namelist.sample.yaml` | Example namelist showing every field. |
| `run.log` | Log of the last `reorganize.py` run. |
| `rename_plan.csv` | Generated by `reorganize.py --dry-run` for user review before `--execute`. |

## Prerequisites

```
pip install pyyaml PyQt5
```

Tested on Windows 11 with Python 3.11+.

## End-to-end workflow

### Step 0 — Back up

```bash
robocopy D:\Chamber  E:\Chamber_backup_20260424  /MIR /XJ
```

### Step 1 — Review the catalog

Open `instruments.yaml`. Verify:
* Serials listed under **Known serials** look correct.
* `legacy_paths` for each instrument still match what exists under `D:\Chamber`.

Fill in **any** serials you already know that are listed as empty; this makes
life easier later. (You can also defer and fill later via
`reorganize.py --update-serials`.)

### Step 2 — Dry-run the reorganization

```bash
cd D:\Chamber\_reorg
python reorganize.py --dry-run
```

Outputs `rename_plan.csv`. Open it in Excel and confirm every
`old -> new` mapping. No files are touched.

### Step 3 — Execute reorganization

```bash
python reorganize.py --execute
```

Type `yes` to confirm. The script will:
1. Copy every source folder to `D:\Chamber\_archive_pre_reorg\` (safety net).
2. Rename / merge into `D:\Chamber\01_instruments\{code}\`.
3. Move non-instrument folders (`etc`, `files`, `YSU`, `PNU`, etc.) to their
   target homes (`00_tools`, `00_resources`, `02_campaigns_legacy`, …).
4. Log every action to `_reorg/run.log` and
   `01_instruments/_meta/merge_log.csv`.

If something looks wrong:

```bash
python reorganize.py --rollback
```

Once you're satisfied (recommend: wait 24 h), delete `_archive_pre_reorg\`
manually to reclaim disk space.

### Step 4 — Fill remaining serials

Open `serials_to_fill.md`, inspect each device, and record SNs.
For each filled entry:

1. Edit `instruments.yaml`:
   - `serial: "<new SN>"`
   - `code:  "<MODEL>_SN<new SN>"`
   - `path:  "01_instruments/<MODEL>_SN<new SN>"`
2. Run `python reorganize.py --update-serials` — folders are renamed in place.

### Step 5 — Build a project from a namelist

Two options.

**A. GUI (recommended)**

```bash
python chamber_gui.py
```

1. Fill project metadata (name, dates, site, PI, operators).
2. Click **Apply to all instruments** if all instruments share the project dates.
3. Tick each instrument used; adjust per-row Start/End if it differs.
4. Pick a copy mode: `hardlink` (default — space-efficient), `copy` (full
   duplicate), or `symlink` (Windows needs Developer Mode).
5. Click **Save namelist…** to persist a copy.
6. Click **Preview (dry-run)** to see file counts.
7. Click **Build project ▶**. Output streams into the log pane.
   The project is created at `D:\Chamber\03_projects\{project_name}\`.

**B. CLI**

Copy `namelist.sample.yaml` to `namelist.MYPROJECT.yaml`, edit, then:

```bash
python build_project.py namelist.MYPROJECT.yaml --preview   # report only
python build_project.py namelist.MYPROJECT.yaml             # build
python build_project.py namelist.MYPROJECT.yaml --rollback  # delete project
```

### Step 6 — Project folder contents

```
03_projects\<project_name>\
├─ namelist.yaml                   # exact config used to build this folder
├─ README.md                       # auto-generated summary
├─ _log\
│   ├─ copy_manifest.csv           # one row per placed file (src, dst, sha256)
│   └─ run.log                     # log for this build
├─ CCN200_SN2310-057\              # per-instrument subfolder
│   └─ ... (filtered data)
├─ CPC3750_SN3750221105\
├─ SMPS_SN7002_CPC3750221105\
└─ PROMO2000_SN22659\
```

The per-instrument subfolder preserves the **original relative paths** from
`01_instruments/`, so existing post-processing scripts keep working when
pointed at `03_projects/<project>/<code>/` instead of `01_instruments/<code>/`.

## How date filtering works

Each instrument entry in `instruments.yaml` declares `date_source`, plus an
optional `date_regex` and `date_format`:

| `date_source` | Meaning |
|---|---|
| `filename` | Parse the filename using `date_regex` (groups are concatenated). |
| `folder` | Walk parent folder names; use the first one matching `date_format`. |
| `file_mtime` | Use the file's last-modified timestamp. |

Fallback: if parsing fails, `file_mtime` is used.

## Troubleshooting

**GUI won't start** — `pip install PyQt5`. Test with `python -c "from PyQt5 import QtWidgets; print('ok')"`.

**`hardlink` copy mode falls back to `copy`** — hardlinks only work within
one volume. If `_reorg/` and the instrument files live on different drives,
use `copy` or move both to the same drive.

**Instrument files not found during build** — check that
`instruments.yaml` → `code:` matches a real folder under `01_instruments/`,
and that `file_patterns` cover your file extensions.

**Merge conflicts during reorganize** — two source files with the same
relative path but different content were kept separately under
`01_instruments/<code>/_conflicts/<orig_folder>/...`. Inspect, keep the
correct one, delete the other.

## Safety notes

- `reorganize.py --execute` always copies originals to `_archive_pre_reorg\`
  **first** (unless `--no-archive` is passed). Rollback is possible until you
  delete that folder.
- `build_project.py` never modifies files under `01_instruments/` — it only
  reads them and places copies/links under `03_projects/`.
- Hash verification (SHA256) runs during merge conflict detection and on
  placed files smaller than 64 MB (recorded in `copy_manifest.csv`).
